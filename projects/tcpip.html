PROJECT OVERVIEW

Exploring the TCP/IP Protocol Suite

This project was completed for the Data Communication and Network course at Universiti Teknologi PETRONAS.

The project focused on understanding how common TCP/IP application-layer protocols operate in practical network environments.

Network environments were configured using simulation tools, followed by connectivity testing and protocol implementation.

Wireshark was then used to capture and analyse network traffic, allowing the team to observe how protocols communicate between clients, routers and servers.

PROJECT OBJECTIVES

From network configuration to packet analysis

Understand Protocols

Explore the purpose, behaviour and characteristics of commonly used TCP/IP application-layer protocols.

Configure Networks

Configure clients, servers, routers, IP addresses and network services within simulated environments.

Test Connectivity

Validate communication between devices using ping tests and network-routing verification.

Analyse Traffic

Capture protocol traffic using Wireshark and examine packet exchanges, responses and security characteristics.

PROTOCOL 01

HTTP

The HTTP implementation demonstrated communication between a client and web server through configured routers.

The network was configured with client, server and router IP addresses before connectivity was validated using a ping test.

An HTTP service was enabled on the server, allowing the client to access and download a test file through the network.

Wireshark traffic analysis identified an HTTP GET request from the client and an HTTP 200 OK response from the server, demonstrating a successful client-server HTTP interaction.

PROTOCOL 02

DNS

The DNS section explored how human-readable domain names are translated into IP addresses through the domain-name system.

A DNS server was configured with multiple record types including A records and CNAME records.

DNS resolution was then verified using nslookup from client devices to confirm that configured domain names resolved to the correct IP addresses.

The exercise demonstrated the importance of DNS for name resolution, service accessibility and scalable network communication.

PROTOCOL 03

Telnet vs SSH

Comparing insecure and secure remote-access protocols.

TELNET

Unencrypted Communication

Telnet transmits communication without encryption, meaning usernames, passwords and transmitted information can potentially be observed by an attacker capturing network traffic.

  • Plain-text communication
  • Basic authentication
  • Greater security exposure
  • Suitable mainly for trusted environments
SSH

Encrypted Communication

SSH provides secure remote access by encrypting communication between devices and supporting stronger authentication methods.

  • Encrypted communication
  • Stronger authentication
  • Protection against surveillance
  • Preferred for secure remote access

SECURITY ANALYSIS

Traffic comparison with Wireshark

Telnet and SSH traffic were captured using Wireshark to compare how each protocol behaves at the packet level.

The analysis demonstrated the security difference between protocols that transmit information without encryption and protocols designed for encrypted remote communication.

This exercise reinforced why SSH is generally preferred over Telnet when remote access needs to be performed securely.

PROTOCOL 04

FTP & TFTP

FTP

File Transfer Protocol

FTP was configured to demonstrate file-transfer operations between network devices.

  • Supports user authentication
  • Suitable for larger file transfers
  • Supports file management operations
  • Uses separate command and data communication
TFTP

Trivial File Transfer Protocol

TFTP provides a simpler and more lightweight method for transferring files across a network.

  • Lightweight protocol
  • Uses UDP
  • Minimal authentication
  • Common in trusted local environments

PACKET ANALYSIS

File-transfer traffic

Wireshark analysis captured FTP traffic containing commands used to upload, list and delete files.

The traffic included responses indicating successful connection establishment, directory operations and completed transfers.

TFTP traffic was also examined, including read requests and an observed timeout condition during one of the transfer attempts.

This provided practical exposure to both successful network communication and troubleshooting unexpected protocol behaviour.
